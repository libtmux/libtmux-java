# Java library pattern study

The study uses released source, not examples copied from unpinned documentation.
Each candidate contributes a narrow pattern or a falsifiable counterexample; no
library is adopted wholesale.

## Pattern decisions

| Concern                  | Evaluated source          | Reusable pattern                                                                                                                             | Rejected part                                                                                                                                              | Effect on a bakeoff gate                                                                                                                                                                                |
| ------------------------ | ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Convention plugins       | Gradle `v9.7.0`           | Put shared Java and publication policy in tested precompiled convention plugins in a dedicated included `build-logic` build.                 | Root-wide `subprojects` mutation and duplicated module scripts hide ownership.                                                                             | All contenders expose identical `hardGates`, publication, and verification tasks; edits to one convention are observed in every module.                                                                 |
| Central publication      | Vanniktech `0.37.0`       | Configure Central deployment, complete POM metadata, source/Javadoc artifacts, and signing through one released plugin surface.              | Hand-rolled repository URLs, task-name coupling, and unconditional snapshot signing duplicate policy already encoded by the plugin.                        | A fresh Maven and Gradle consumer must resolve each locally published coordinate, while the artifact oracle checks signatures, metadata, source, and Javadoc contents.                                  |
| Annotation contract      | JSpecify `v1.0.0`         | Null-mark exported packages and use type-use `Nullable`; keep the annotation artifact build-only while retaining class-file annotations.     | Home-grown nullness annotations and using `Optional` as a substitute for parameter, field, generic, or element nullness create a second vocabulary.        | Plain consumers compile and run without JSpecify; an opt-in analyzer consumer reads the retained annotations; core runtime graphs remain empty.                                                         |
| Processor execution      | QueryDSL `QUERYDSL_5_1_0` | Treat each nonterminal JSR 269 round explicitly and create sources through the provided `Filer` with originating elements.                   | QueryDSL's general entity model, serializer hierarchy, and dependency graph exceed the closed libtmux field metamodel.                                     | Generated types must be deterministic across clean builds, declare originating elements, appear in binary/source/Javadoc jars, and leave no processor dependency in core metadata.                      |
| Golden processor tests   | compile-testing `v0.23.0` | Compile in-memory sources with an explicit processor and compare generated source through compiler-aware assertions.                         | A text-template snapshot without compilation can accept invalid imports, inaccessible types, or malformed Java.                                            | The processor bakeoff compares exact generated source and compiles a downstream consumer of that source.                                                                                                |
| Compile-fail tests       | compile-testing `v0.23.0` | Assert compilation failure and diagnostic fragments with a controlled classpath and processor path.                                          | Success-only golden tests cannot prove that invalid field/operator combinations are rejected by Java's type system.                                        | Negative fixtures must fail for string operators on non-string fields, inaccessible internals, invalid relation operands, and nullness violations; an unrelated syntax error must not satisfy the gate. |
| JUnit resource ownership | JUnit Framework `r5.14.4` | Store per-context state in a namespaced `ExtensionContext.Store`; make owned state `AutoCloseable` so store closure is the cleanup backstop. | Extension instance fields plus only `BeforeEachCallback`/`AfterEachCallback` rely on callback symmetry and are unsafe under parallel or aborted execution. | Parallel, setup-failure, test-failure, and teardown-failure fixtures must leave no tmux server or helper process and must preserve suppressed cleanup failures.                                         |
| Immutable graph shape    | Guava `v33.4.8`           | Preserve encounter order, make copy boundaries explicit, validate self-loop/cardinality rules at construction, and expose immutable results. | Shipping Guava's generalized graph abstraction would add a core dependency and expose live-view semantics unrelated to the closed tmux hierarchy.          | Snapshot fixtures assert stable session/window/pane order, linked-window identity, immutable collections, and deterministic point resolution using dependency-free Java values.                         |

## Counterexample matrix

Every provisional winner has an explicit falsifier rather than only confirming
evidence.

| Provisional winner                        | Source-backed counterexample                                                                                                                                                                                                                                                                                                                                             | Rejection condition                                                                                                                                    |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Included `build-logic` convention build   | Gradle's [`buildSrc` lifecycle](https://github.com/gradle/gradle/blob/v9.7.0/platforms/documentation/docs/src/docs/userguide/structuring-builds/sharing_build_logic_between_subprojects.adoc#L139-L195) compiles before the main build, permits only one root instance, and invalidates configuration after changes.                                                     | Reject the winner if it cannot match `buildSrc` convenience while keeping build logic independently testable and its invalidation boundary measurable. |
| Released publication plugin               | Vanniktech's [top-level plugin](https://github.com/vanniktech/gradle-maven-publish-plugin/blob/0.37.0/plugin/src/main/kotlin/com/vanniktech/maven/publish/MavenPublishPlugin.kt#L6-L22) automatically wires Central and signing from properties.                                                                                                                         | Reject it if convention-plugin application cannot disable remote publication during local spikes or if generated metadata differs across modules.      |
| JSpecify compile-only contract            | JSpecify retains annotations at [runtime](https://github.com/jspecify/jspecify/blob/v1.0.0/src/main/java/org/jspecify/annotations/NullMarked.java#L109-L112), so stripping annotations from artifacts would erase the contract.                                                                                                                                          | Reject any dependency-free technique that also removes class-file annotation evidence; omit only the runtime dependency edge.                          |
| Small custom JSR 269 processor            | QueryDSL's [two-pass element processing](https://github.com/querydsl/querydsl/blob/QUERYDSL_5_1_0/querydsl-apt/src/main/java/com/querydsl/apt/AbstractQuerydslProcessor.java#L111-L130) shows that derived relations may require more than a single flat scan.                                                                                                           | Reject a one-pass implementation if relation metadata is order-dependent or unresolved across rounds.                                                  |
| compile-testing golden and negative tests | compile-testing's [generated-source test](https://github.com/google/compile-testing/blob/v0.23.0/src/test/java/com/google/testing/compile/CompilationTest.java#L80-L105) and [empty-classpath failure](https://github.com/google/compile-testing/blob/v0.23.0/src/test/java/com/google/testing/compile/CompilerTest.java#L125-L151) exercise different failure surfaces. | Reject a single combined assertion if it cannot distinguish wrong generated text from a missing dependency or expected type error.                     |
| Store-owned JUnit fixture state           | JUnit documents that manually [`remove`](https://github.com/junit-team/junit-framework/blob/r5.14.4/junit-jupiter-api/src/main/java/org/junit/jupiter/api/extension/ExtensionContext.java#L735-L750) does not trigger automatic close.                                                                                                                                   | Reject fixture code that removes owned resources before explicitly closing them or that stores borrowed resources as auto-closeable owned state.       |
| Dependency-free immutable hierarchy       | Guava's builder intentionally exposes [self-loop and ordering policy](https://github.com/google/guava/blob/v33.4.8/guava/src/com/google/common/graph/GraphBuilder.java#L91-L140).                                                                                                                                                                                        | Reject a minimal hierarchy if it silently accepts duplicate IDs, loses encounter order, or cannot represent one window linked into multiple sessions.  |
